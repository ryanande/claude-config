2. **Asset-delete failures were misdiagnosed — they were shared-view read failures** — _Fleet vehicle-mgmt working chat_ (`meeting_ZTQ1YjY2…`).
   Clinton Landry landed the correction: "those aren't delete failures at all" — failed SQL reads against `dbo.vw_Asset` for the exact asset ids, timestamps lining up with the delete attempts. Wyatt Rupp had the timeline (PR #127 merged 16:13Z, Host redeployed alpha.323 16:25Z, `DeleteAssetHandler` failing 18:04Z); Carson Darling surfaced `sp_getapplock returned -1` on the account delete lock.
   **Why it matters:** The debugging is excellent — root cause moved from "delete is broken" to "the read the delete depends on is timing out." But the mechanism it exposes is two Autonomous Services smells at once: a delete path reading through a shared SQL view, and cross-service mutual exclusion implemented as a database application lock. In a message-based design that coordination belongs in message ordering and idempotency, not `sp_getapplock`. It's also an Observable Services finding — the failure wore the wrong error for hours because the read failure wasn't instrumented distinctly from the delete failure.
   **Action:** Bless the diagnosis publicly, then challenge the mechanism: `sp_getapplock` as a cross-service coordination primitive needs an ADR or removal. Separately, ask for the read failure to surface as its own error class so the next occurrence self-diagnoses instead of costing a night.

4. **`accountNumber → accountId` resolver flagged as tech debt, with an aggregate-boundary question underneath** — _Fleet vehicle-mgmt working chat_ (`meeting_ZTQ1YjY2…`).
   Clinton Landry: the resolver is "a holdover from when we did not load cost centers… Should probably be tech debt and use the GUID from AssetGroupId."    **Why it matters:** This is Build Apps the Way the Business Works in miniature. The code models one flat account per asset; the business has a parent/cost-center hierarchy where the account that matters is the child. Resolving by account *number* through a lookup rather than carrying the identity GUID is exactly where that mismatch hides.    **Action:** Reframe from tech debt to aggregate boundary. Confirm whether asset→account is genuinely one-to-one, or whether cost-center hierarchy belongs in the model. Get "account", "cost center", and "asset group" into the domain glossary before the refactor, not after.

## 🧠 Knowledge opportunities

- **"Do we own X database?" is now a recurring question with no owner.** Naomi Gallagher asked "do we own the PrepassInform DB?" (`meeting_ZWI4ZjNl…`); AccountPlates raised the same shape today; the ElasticSearch ownership thread raised it yesterday. Three data-store ownership questions in two days is a missing artifact, not three coincidences. Candidate: a data-store ownership table in `dx-prepass-meta/docs/` — or better, an arch-rover scan, since it's Class 1 scannable fact.
- **Config-key → env-var → Key Vault secret naming is undocumented.** Clinton had to guess what `--` does in `AccountPlates--ConnectionString` and said he'd ask an LLM. The `:` / `__` / `--` mapping chain is standard .NET config plumbing and costs a paragraph to write down once in the template docs. It will otherwise be re-derived by every service that adds a secret.
- **Nothing tells teams what to use instead of a database lock.** The distributed-design Confluence set covers eventual consistency, validation, and read models, but has no page on cross-service mutual exclusion — which is why `sp_getapplock` looked like a reasonable answer. Worth a short page alongside "Validation in a Distributed World."
- **Registers claim "verified" without evidence.** PRS.md #106 asserted resolved and live-smoke-verified for a connection string that was empty in INT. A convention that verified claims carry a run link would make these artifacts self-checking rather than aspirational.
- **The story-dependency session is working — capture why.** Yesterday flagged that refinement had been repurposed toward dependencies and splitting; today's recap (`meeting_MGVjN2JlNTg…`) reports several stories dropped as unnecessary or out-of-bounds, and Andrew Love separately purged the FMP and UP backlogs to MVP-only.
